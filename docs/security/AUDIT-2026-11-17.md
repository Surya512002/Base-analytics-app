# Security & transaction audit — 2026-11-17

Scope: Lend & Stake (Smart Deposit / Withdraw, Get-token), Swap, API routes, secrets, headers,
dependencies. Method: code review plus mainnet testing with `eth_simulateV1` and state
overrides. A throwaway address is given USDC / ETH / vault shares, and the exact batches the app
sends run against live Base state. **No real transactions were signed or sent** (trading and
moving funds stays with the owner). Scripts: `scripts/audit/`.

## 1. x402 facilitator gas drain (Critical)

`verify` / `settle` took both the signed payment *and* the requirements from the request body,
then the facilitator's hot wallet submitted the transfer. Anyone could sign tiny USDC
authorizations between their own wallets and loop `settle`.

Fix: `lib/x402-policy.ts`. Only `exact` USDC payments on Base **to the app treasury**, $0.01–$1,000,
are verified or settled; everything else is refused before signing. Live check:
settle to a foreign payee → `"payee is not this app"`.

## 2. Stored XSS via uploads (High)

`/api/launchpad/upload` trusted `file.type` and `/api/launchpad/media/[id]` echoed it back as
`Content-Type` from our origin. Fix (`lib/launchpad/image-sniff.ts`): the type is detected from the
bytes (PNG / JPEG / WebP / GIF only); media is served only if the bytes are a raster image, with
`nosniff` and a sandboxing CSP; uploads are rate-limited (10 / 10 min / IP). Live check: SVG
upload → 400.

## 3–4. Atomic, minimal-approval transactions (High / Medium)

Browser wallets (MetaMask, Rabby) deliberately don't batch (EIP-7702 prompt), so every call was
its own transaction. New: Beefy's audited **Zap Router** on Base (`0x6F19…6a63`, TokenManager
`0x3fBD…c0f0`; selectors verified in bytecode, `paused()` checked at runtime with fallback).

The user signs at most an exact `approve(TokenManager, amount)` (skipped if already covered) and
one `executeOrder`. Swaps, liquidity add and stake run inside one transaction; outputs are
checked on-chain and leftovers returned. The router approves the swap router / CLM / vault for
its own balance; the user never approves those.

Mainnet results (live state):

| Flow | Before | After |
|---|---|---|
| Smart Deposit with USDC | 4 tx, 2 approvals | **2 tx, 1 exact approval** |
| Smart Deposit with ETH | 5 tx | **1 tx, no approval** |
| Vault → all USDC | 4 tx (22.44 USDC + dust) | **2 tx (22.61 USDC, no dust)** |
| CoW shares → all USDC | 3 tx | **2 tx**, more USDC |
| Get NVDAc with ETH | 3 tx | **1 tx, no approval** |
| Swap: buy with USDC (browser wallet) | 3–6 prompts | **2** |
| Swap: buy with ETH | 2–4 prompts | **1** |

Leftover allowances after every flow: **0**. Swaps give identical output and treasury fee
before/after wrapping. The drawer also re-plans at the click and, on browser wallets, re-plans the
order after the approval is mined, so minimums are never stale. Swap approvals are now exactly
what the router pulls (net of the fee on router paths).

## "First deposit failed, second worked"

Reproduced: Beefy CLMs revert with `NotCalm` (`0x26c87876`) while the pool price is off its
2-minute TWAP (`strategy.isCalm() == false`; observed toggling within seconds during this audit).
On a browser wallet the approval landed, then the separate deposit hit that window. The atomic
order removes the gap, the drawer re-plans and simulates right before signing, and both deposit
and withdraw buttons now pause (with a message) while the pool isn't calm.

## 5–7. API authorization

- Announcements: require a SIWE session for the creator address + rate limit.
- Vouchers: stored metadata now comes from `getBatch` on-chain (only a validated `txHash` /
  `createdAt` from the client); `PATCH` refreshes the redeemed count from the contract.
- Compliance: `lib/compliance/request-country.ts`. On Vercel only `x-vercel-ip-country` counts;
  mock headers work only outside Vercel (local dev, e2e).
